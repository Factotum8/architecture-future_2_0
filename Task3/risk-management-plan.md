# План управления рисками

## 1. Принципы

- **Сначала контракты и границы доменов**, затем масштабирование интеграций.
- **Security и комплаенс by design** для медицинских и финансовых потоков.
- **Поэтапное снижение легаси**: явные «мосты», сроки жизни, антикоррупционные слои.
- **Измеримость**: SLO на критичные цепочки, DQ и FinOps как обязательные дисциплины.

## 2. Меры по группам рисков

### Архитектура

| ID | Меры снижения                                                                                                                                                                         | Преимущественно                                                                               |
|----|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| A1 | Единый каталог схем событий и витрин; выделенные «источники истины» по доменам; периодическая сверка метрик между потоками и витринами; поэтапное отключение дублирующей логики в DWH | Техн.: каталог, пайплайны, тесты консистентности. Управл.: data governance, владельцы доменов |
| A2 | Горизонтальное масширование брокера, квоты, изоляция кластеров/namespace по доменам; нагрузочные тесты; резервирование                                                                | Техн.: платформа, SRE. Управл.: планирование ёмкости, бюджеты                                 |
| A3 | Обязательные схемы (Avro/JSON Schema), ревью breaking changes, совместимость версий, контрактное тестирование                                                                         | Техн.: CI, реестр схем. Управл.: процесс изменений API/событий                                |
| A4 | Дорожная карта вывода Camel/DWH с вехами; антикоррупционные слои; KPI «доля трафика через мосты»                                                                                      | Техн.: рефакторинг, адаптеры. Управл.: приоритизация бэклога, отчётность руководству          |

| ID | Меры снижения                                                                                                                               | Преимущественно                                                       |
|----|---------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------|

### Технологии и безопасность

| ID | Меры снижения                                                                                                                       | Преимущественно                                                        |
|----|-------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------|
| T1 | RBAC/ABAC на портале; маскирование; минимизация данных; аудит обращений; запрет сырой PHI в витрине (как в ТЗ)                      | Техн.: IAM, шифрование, DLP. Управл.: политики, обучение пользователей |
| T3 | FinOps: бюджеты по доменам, алерты по расходам, правая-sizing, reserved capacity где уместно                                        | Управл.: бюджет. Техн.: метрики облака, политики                       |
| T4 | Абстракции (Kubernetes, стандартные API), документирование exit-стратегии; избегать глубокой привязки к проприетарным API без нужды | Техн.: архитектура. Управл.: оценка контрактов с вендорами             |
| T5 | Единая наблюдаемость; SLO/SLI; качество данных как код; алерты на аномалии и задержки пайплайнов                                    | Техн.: стек observability, DQ. Управл.: дежурства, эскалации           |

## 3. Что закрывается техникой, что — управлением

- **В первую очередь техническими средствами:** 
контракты событий, шифрование, IAM, идемпотентность, мониторинг, инфраструктура как код, каталог данных, 
антикоррупционные слои, автотесты консистентности.
- **В первую очередь управленческими:** 
границы ответственности доменов, приоритизация и финансирование, обучение и найм, согласования с ИБ/регуляторикой, 
культура работы с изменениями, FinOps-гигиена на уровне руководства.
